# Event Storm: 学术论文生产（academic-paper）

> Date: 2026-10-23
> Roles: product-manager · architect（studio-planner 内置）· research-advisor · peer-reviewer（studio/agents/ 本项目专家）
> Mode: 快速模式（四角色各自列事件后合并去重；画像 / 旅程 / 流程各取最小集）

## Domain Context

**领域**：计算机学科课题组（PI + 博士 / 硕士）产出软件工程 / AI 系统方向的会议论文（ICSE / FSE / ASE / NeurIPS systems / MLSys 类），从选题到发表的全生命周期。

**现状**：文献散在各人笔记；研究问题（RQ）和判据与导师口头约定；实验结果躺在日志和表格里，失败与负结果无人登记；内审是导师临投稿前读一遍；rebuttal 几天内赶出来，证据临时翻。

**期望改变**：一条插件管线把 **定位（文献矩阵 / 论点句 / 最近邻差异）→ 开题（RQ / 假设 / 判据预登记 / 图表规划）→ 实验台账（每次 run 含负结果，映射 RQ）→ 内审与回应（按目标会议评审表的模拟评审、逐条回应表）** 做成有闸门、留痕、可回指的证据链。**正文写作与导出交给 studio-docs**（本域只产出证据包与一份学术论文 blueprint 需求，不造写作功能）。

**第一篇要用这条管线写的论文**：自进化的行业基石大模型（studio-evolve 的动态本体构建 → 仿真加强 → 自生长迭代，三轴评价 长高 / 长壮 / 长胖）。

## 待用户裁定（进入 domain-model 前）

1. **导师闸门放在哪**：建议 E4 论点句、E6 判据冻结、E13 结果冻结、E17 fatal 处置、E19 投稿 五处必须人批，其余不拦（架构师建议三处，审稿人加了两处）。
2. **台账预注册还是事后补录**：导师坚持「判据先于正式实验」；架构师担心摩擦。折中：正式 run 必须在判据冻结之后，但允许「探索性」run 随时入账、事后不能升级为正式。
3. **实验日志格式**：课题组现用 wandb / tensorboard / 裸日志？决定台账是「导入 + 校验」还是「手填 + 校验」。第一篇论文（studio-evolve）的台账来源是 `.studio-evolve/{id}/ledger/growth-ledger.md`，可先按它做导入。
4. **插件形态**：架构师建议 core + add-on（`paper-core` 定位 / 开题 / 台账 / 证据包；`paper-review` 内审 / rebuttal 可选；`paper-search` 检索 MCP 可选）。是否接受拆分，domain-model 阶段定。
